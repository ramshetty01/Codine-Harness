# Automatic semantic and active-turn compaction (C2/C3)

When the next normal request exceeds its character or estimated-token budget,
Codine attempts **one real provider summary request**. This is inference, not string
truncation renamed as summarization. It uses the selected model, normal output cap,
and the same reservation/settlement path as generation. OpenRouter session charges,
evaluation guards, pending-charge blocks and actual token usage include summaries.
No summary request bypasses the configured budget or retries automatically.

The summarizer receives a bounded prefix of complete conversation groups, the prior
summary and the current durable task plan. It receives no tools. Its dedicated
instruction requests JSON arrays for `constraints`, `decisions`, `files`, `tests`
and `unresolved`. File hashes and observed tool metadata (path, SHA256, status,
exit code, passed/ok/error) are also preserved verbatim in a separate evidence list.
This deterministic evidence is not regenerated by the summarizing model.

The persisted session holds `context_summary`, `summary_end` and an optional
`summary_user` anchor. It never edits or deletes the source conversation, including
opaque provider reasoning. Request projection substitutes the summary for the
covered prefix. A summary covering part of the active turn retains that turn's
original user message verbatim. Current task-plan state is injected afresh into
normal requests and summary payloads; model summaries cannot mutate that plan.

A tool-call group means the assistant request and **every** matching tool result.
Prefixes end only after a complete assistant answer or a complete tool group. They
never cut between parallel calls and their results. Active-turn compaction runs
between tool batches, after the pending journal is committed, so it cannot hide an
unfinished side effect. The source archive continues to satisfy normal tool-pair
validation; resumed summary boundaries are validated independently.

The summary appears as an explicitly labeled untrusted user-data message, not as
new system instructions or permission authority. It can influence the model as
context, like other task data. Provider summarization is fallible: a valid JSON
shape cannot prove all semantic constraints were retained. The instructions request
preservation, the original archive remains available, and observed identity/result
metadata plus the active user task and plan are retained separately. These tests
are not evidence of prompt-injection immunity or perfect summarizer quality.

## Failure behavior

Both the summary request and resulting normal request must fit existing input and
output-reservation limits. A single oversized tool result is not silently chopped
into arbitrary fragments. If no complete prefix fits, Codine stops without making
a summary request. If a summary is malformed, empty, truncated, requests tools, or
still cannot make the normal request fit, Codine stops without replacing the old
context metadata. The summary call may already have incurred its recorded charge.
There is no recursive summarize-the-summary loop or automatic retry.

Timeouts, cancellation and unknown charges keep the normal pending reservation and
block subsequent requests until reconciliation. Successfully generated summaries
survive resume. `/clear` moves the active context past earlier summaries, so they
are not silently reintroduced. The existing `/compact` command remains explicitly
manual recent-turn selection; it is not a semantic summary request.

`/context` uses the same strict projection, plan and summary state as the next
normal request. It reports summary coverage but makes no provider call. An
over-limit report means a bounded compaction attempt will be needed; it does not
pretend the future summary or its cost is already known.

## Verification

`tests/test_semantic_compaction.py` uses fake providers to verify the extra summary
call and its charges, plan preservation, unchanged opaque archive, active-turn
hash/result preservation, parallel-call boundaries, invalid/truncated/oversized
summary rejection, unknown-cost and timeout blocking, corrupt saved boundaries,
and clear/resume behavior. No paid inference was used to validate this feature.
Actual summary quality on models remains a live-evaluation gate.
